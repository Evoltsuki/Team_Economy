# Team Economy 1.0.1 平衡配置指南

## 买价、回收价与交易范围

买卖不是同价。普通商品的购买价至少为基础回收价 × `shop.buyMarkup`，默认和允许的最低值均为 **2.0**；稀有物品、附魔书和设备另有售价下限。回收收入会按材料组需求递减，购买价不随这个递减一起下降。

| 商品 | 默认购买底价 |
|---|---:|
| 美西螈桶 | 8,192 |
| 蝌蚪桶、热带鱼桶、河豚桶 | 2,048 |
| 鳕鱼桶、鲑鱼桶 | 768 |
| 潜影壳、远古残骸、回响碎片、海绵 | 4,096 |
| 下界合金锭、三叉戟、海洋之心、嗅探兽蛋 | 24,576 |
| 经验修补附魔书 | 65,536 |

表中是默认底价，实际取通用估价与底价的较大值；钻石基础价高于 256 时，这些底价还会同比提高。价格只决定花费，**不会解锁本来禁止购买的商品**。例如鞘翅、下界之星、重锤、试炼钥匙、锻造模板和下界合金成品装备仍只回收不出售。

**第三方 MOD 物品默认不出售，服主可在 `teamecon_shop_catalog.json` 中逐项添加售价后上架**；回收默认关闭，服主可用 `/teamecon admin prices` 为单件物品设置回收价，仅接受默认状态的第三方物品。第三方附魔不出售。仅修改基础估价或进度规则不会自动上架第三方商品。具体格式见[商店与盲盒配置](server-configuration.md)。本模组游戏机、商店、盲盒机、终端及刮卡有专用获取入口；本模组物品不能回收。

普通购买仍检查原版进度：铁、钻石、下界、末地等材料须先达到相应阶段；附魔书需先完成附魔进度，经验修补额外检查交易进度。进度属于操作玩家，共享钱包不等于共享个人进度。

**盲盒是独立例外**：仅从盲盒机打开，默认无进度或等级门槛，可配置阶段门槛；开启前可查看服务器真实奖池。普通商店和终端没有盲盒页。一次开 1／10／64 个，先检查整批可能组合的空间，再抽取、扣费与交付；空间不足整批拒绝。

1.0 默认物资箱 64 点、11 个奖项；珍藏箱 512 点、54 个奖项。两池均无空奖、腐肉，含钻石及下界合金等高价值奖品。珍藏箱有 43 种友好／中立生物刷怪蛋，合计概率 10%，单种权重 23 或 24，总权重 10,000。刷怪蛋不能购买或回收。概率明细见试玩指南或游戏内奖池悬停提示。自定义空奖仍兼容。

## 食物购买价格

食物采购使用独立购买底价，回收收入按基础估价与市场需求计算。默认土豆 8、生肉 16、面包／烤土豆 24、牛排／熟猪排 32、炖菜 40、南瓜派 48、蛋糕 96、金胡萝卜 128 点。起始 200 点只能买 6 块牛排，商店适合应急，种养烹饪仍有价值。腐肉等低效食物也有底价，避免成为廉价补给漏洞。实际售价取普通估价与底价的较大值；服主显式覆盖仍优先。

## 前期流程与后期收入

全新个人开局默认领取 **200 点**启动资金。发放有一次性领取记录，已存在的钱包不会重复获得；新建或切换队伍不会复制个人启动资金。Lv.1 → Lv.2 费用为 **1,200 点**。回收正常采集物资即可升级，不要求靠游戏赢钱。

以默认基础价格、各材料组需求全新、忽略交易过程中的恢复为例：出售 **32 铁锭、32 铜锭、8 金锭，以及各 64 个煤炭、橡木原木、小麦、圆石**，按实际需求曲线累计约 1,150.75 点，先入账 1,150 点，其余小数留存。加起始 200 点约有 1,350 点，可支付首次升级。机器本身仍需另行合成或购买；保留需要的工具材料，不必照此清单出售。

需求倍率为 `max(0.05, 0.99^d)`，成交使用消耗区间的积分。大量出售同一种材料收益会下降；铁粒／铁锭／铁块等可逆材料共用需求，分堆或压块不增加结算收益。27 格批量回收按同一时刻逐组累计报价，小数收入保留；钱包不能接收整批时不扣物品，不支持的物品留在格子里。

后期可以大量补购普通建材和已经解锁的物资，这是商店的用途。关键战利品禁购、原版进度、稀有购买底价、至少两倍的买卖差价和回收需求递减共同限制跳过探索。各游戏默认都不是正期望收入来源，但单次大奖仍可能很大。

原版无限农场仍能长期积累点数，当前没有购物日配额或自动产量识别，因此不能保证每个服务器永不通胀。服主可根据实际农场产量和消费记录调整基础价、需求下限与恢复速度。

## 等级与早期机器的后期用途

| 钱包等级 | 本次升级费 | 新开放机器 | 刚解锁时单注上限 | Lv.5 时单注上限 | 默认最高奖励倍数 |
|---|---:|---|---:|---:|---:|
| 1 | 免费 | 猜大小 | 2,000 | 50,000 | ×1.8 |
| 2 | 1,200 | 史莱姆跳冰 | 10,000 | 100,000 | 整局 ×40 |
| 3 | 10,000 | 幸运转盘 | 50,000 | 250,000 | ×10 |
| 4 | 50,000 | 黑红轮盘 | 100,000 | 200,000 | 单号 ×32；红黑 ×2 |
| 5 | 200,000 | 老虎机／倍率竞猜 | 各 200,000 | 各 200,000 | ×200／×1,000 |

升至 Lv.5 的升级费合计 **261,200 点**，不含机器或终端。钱包比机器解锁等级高 1／2／3／4 级时，下注上限按 ×2／5／10／25 增长，仍受全局 `gambling.maxBet` 限制。早期机器保持短局、较小波动的用途；高级机器提供更高奖励上限和不同玩法，不只是替换前期机器。

刮卡最高票面按 Lv.1～5 分别为 **100／1,000／10,000／100,000／250,000 点**。票面倍数 1～10,000，票价和奖金同比提高，还须满足对应等级的票面上限。比如 Lv.5 的数字卡可放大到 100,000 点，骰子卡可到 250,000 点，所以早期卡不会只剩几十点的用途。卡的奖级分布不会因为提高票面而变好。

所有奖励倍数包含本金。跳冰的层级是 ×1.2、×1.5、×2、×2.75、×4、×6、×10、×16、×25、×40；后续跳跃持续变难，即使最后一步被自定义上限截短也不会变容易。倍率竞猜采用加速时钟，若一直未崩盘，约 5.9 秒到 ×2、14.45 秒到 ×10、23 秒到 ×100；高倍率尾部额外衰减，×100 极少出现。手册列出事件概率与中奖倍数，不展示具体理论平均返还。

## 配置文件

| 文件 | 用途 |
|---|---|
| `存档/serverconfig/teamecon-server.toml` | 起始余额、全局下注范围、回收需求、购买加价 |
| `config/teamecon_base_prices.json` | 原版物品基础估价锚点 |
| `config/teamecon_shop_catalog.json` | 默认目录开关、下架清单、自定义商品与售价 |
| `config/teamecon_shop_prices.json` | 稀有物品与附魔的独立购买底价 |
| `config/teamecon_progression.json` | 原版商品、附魔的进度与只卖不买规则 |
| `config/teamecon_casino_levels.json` | 五级费用、机器限制、终端条件、卡片等级 |
| `config/teamecon_enchants.json` | 附魔书目录、等级与配置价格 |
| `config/teamecon_blindbox.json` | 独立盲盒价格与奖池 |
| `config/teamecon_slots.json` | 老虎转轴权重与奖表 |
| `config/teamecon_risk_tiers.json` | 风险档配置；竞猜的连续增长时钟由玩法实现决定 |

JSON 修改后执行 `/teamecon admin reload` 或重启。TOML 建议停服修改；已有世界使用自己的 `serverconfig`，不会自动采用整合包新的 `defaultconfigs`。

重要默认值：`economy.startingBalance=200`、`economy.maxBalance=0`（无人工硬上限）、`shop.buyMarkup=2.0`、`gambling.maxBet=1000000`、`gambling.maxMultiplier=1000`、`market.decayPerUnit=0.01`、`market.minPriceFactor=0.05`、`market.recoverySecondsPerUnit=30`。

设备 JSON 中 `maxBet` 是解锁等级的基础上限；`maxRunMultiplier` 控制闯关上限；`payoutScale` 缩放一次性奖励，轮盘默认 1，猜大小默认 0.90。猜大小均匀抽取 1–10，小 1–5、大 6–10，两边仍各 50%；改变数字范围本身不会降低胜率。猜中默认奖励 ×1.8，单次结果有波动。界面显示奖励倍数，不以伪造概率制造误导。

`chanceScale` 调整跳冰风险与竞猜存活分布，竞猜默认 0.83。卡片价格与奖级由 `ScratchKind.java` 定义，刮卡 JSON 不用于配置八种实体卡。

`gambling.expectedValueCap` 是配置校验阈值。调低它会禁用超过阈值的玩法或启用 `enforceValueCap` 的奖池，不会自动等比降低所有奖金。不要用钱包硬上限代替平衡；硬上限可能截断游戏大奖。

## 压缩材料

金块等九合一储存方块使用基础材料的九倍估价，不增加可逆压缩的合成加价。默认金锭 64 点，金块 576 点；实际回收仍受市场需求影响。服主明确配置方块自身基础价时优先使用该值。详见[商店与盲盒配置](server-configuration.md)。
