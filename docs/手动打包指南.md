# 手动打包 Team Economy 1.0.2

版本固定为 **1.0.2**，仅在作者明确要求时修改 `gradle.properties` 中的 `mod_version`。所有命令在项目根目录执行；普通构建不启动游戏。

## 构建单个目标

准备 JDK 21。Forge 1.20.1 还需要 JDK 17，两个 Forge 目标需要 Python 3.11+（Windows 使用 `py`，其他系统使用 `python3`）。

| 目标 | PowerShell 命令 | JAR 输出目录 |
|---|---|---|
| NeoForge 1.21.1 | `.\gradlew.bat releaseMod` | `dist/`，同时保留 `build/libs/` |
| NeoForge 1.21 | `.\gradlew.bat releaseMod '-PmcTarget=1.21'` | `dist/`，同时保留 `build/neoforge-1.21/libs/` |
| Forge 1.20.1 | `.\gradlew.bat -p versions/forge build --no-daemon --no-configuration-cache` | `build/forge-1.20.1/libs/` |
| Forge 1.21.1 | `.\gradlew.bat -p versions/forge build '-Pmc=1.21.1' --no-daemon --no-configuration-cache` | `build/forge-1.21.1/libs/` |

Windows 双击 `build-mod.bat` 等同于默认 NeoForge 1.21.1 构建。Linux/macOS 将 `.\gradlew.bat` 换为 `bash ./gradlew`。首次构建需要联网，完整缓存可加 `--offline`。Forge 两个目标请顺序构建，避免 ForgeGradle 工作目录冲突。

如果 Gradle 没有自动发现 JDK 17，在 Forge 1.20.1 命令后加 `'-Porg.gradle.java.installations.paths=C:\你的JDK17目录'`。该路径属于本机环境，不应写入公开配置。

Forge 业务源码由 `tools/prepare_forge.py` 从 `src/main/` 生成，平台差异位于 `versions/forge/src/`。修改共享源码或适配层，不要修改 `build/forge-*/generated/`。

NeoForge 默认使用各分支的最低正式版本编译：Minecraft 1.21.1 对应 21.1.1，Minecraft 1.21 对应 21.0.143。版本与兼容范围统一在 `gradle.properties` 配置；可用 `-PneoForgeVersion=版本号` 指定同一分支的其他版本进行兼容性检查，该参数不修改发布包声明的最低版本。

## 生成 GitHub 发布附件

安装 Python 3.11+ 和 Pillow，准备 JDK 17 与 JDK 21：

```powershell
py -3.12 -m pip install Pillow==12.3.0
py -3.12 tools/package_release.py --offline
```

需要指定 JDK 17 时加 `--java17 'C:\你的JDK17目录'`。首次构建去掉 `--offline`。脚本依次构建四个目标，核对加载器元数据、Java 字节码和资源，再生成 `release/1.0.2/` 的六个附件：

- `teamecon-neoforge-1.21.1-1.0.2.jar`
- `teamecon-neoforge-1.21-1.0.2.jar`
- `teamecon-forge-1.20.1-1.0.2.jar`
- `teamecon-forge-1.21.1-1.0.2.jar`
- `CHANGELOG.md`
- `SHA256SUMS.txt`：上述五个文件的 SHA-256。

玩家只安装匹配游戏和加载器的一份 JAR，多人服两端使用同一文件。完整打包也会将四份 JAR 与单独校验值复制到 `dist/`。

公开代码、平台适配、工具、文档和图片可从 [GitHub 仓库](https://github.com/Evoltsuki/Team_Economy)获取。仓库按 `tools/package_release.py` 的公开清单维护，本地存档、缓存、构建输出及 `internal/` 不提交。Release 上传以上六个文件。脚本只生成本地文件，不会上传或发帖。

GitHub 中文首页为根目录的 `README.md`，包含玩法、指令、项目目录与源码构建说明。release 版本目录只存上方列出的六个附件。

独立英文版为根目录的 `README_EN.md`，与中文首页一同保留在仓库中。中英文首页分别维护，不自动整篇同步。

若版本目录中存在其他旧命名或额外文件，先归档到 `internal/backups/`，脚本会拒绝混合新旧附件。失败时不要把保留的旧成品当成新构建。

只导出源码，可指定新的空目录：

```powershell
py -3.12 tools/package_release.py --stage build/public-source
```

## 维护与校验

用 `Get-FileHash 'release/1.0.2/文件名.jar' -Algorithm SHA256` 对照 `SHA256SUMS.txt`。单目标包校验可运行 `py -3.12 tools/verify_release.py JAR路径 --loader forge --mc 1.20.1`。

增量构建无需先执行 `clean`。清理 `build/` 前请保留所需的本地文件；`run/` 中的存档应另行备份。其他工具见 [tools/README.md](../tools/README.md)。
